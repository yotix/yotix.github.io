One backbone for a fleet of sites.

Distributed energy sites each produce their own telemetry, and every new site adds another gateway contract to honour. Inno2grid runs one backbone for all of it: an ingest path that every device writes to, one identity layer shared by the services, and a control plane that decides what each gateway does next.

Thirty engineers carry the whole thing, so the person who changes the schema also watches the dashboards it feeds.

The problem

A gateway fleet grows sideways: each new site arrives with its own constraints, and every one of them needs its readings to land somewhere that answers questions later. Without one ingest path and one identity layer, the ninth site costs more than the first eight together.

The aim was a backbone that a new site joins in an afternoon, with the audit trail already in place.

Three layers, no duplicates.

Approach
I

Write once, read many

Devices publish to a single ingest path. Dashboards, exports and the regulator-facing report are read models of that stream rather than four caches to keep in step.

II

One identity layer

Gateways and services authenticate against shared IAM instead of per-service tokens, so a device that is onboarded once works everywhere it is deployed.

III

The control plane explains itself

Each gateway gets its assignment, its window and a reason. A field technician can read why a device is behaving as it is without opening a code editor.
